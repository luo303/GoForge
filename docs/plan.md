# MindOS 开发计划

本计划以**质量与验收完成度**为进度，不设置工期，不以提交数量衡量速度。原 Phase 1–8 拆为 Phase 1–21，每个阶段只增加一层可独立验证的能力。

## 1. 执行原则

1. **顺序推进**：默认不跨阶段开发；后续阶段不得替前期补测试、补错误处理或补文档。
2. **小步提交**：下列提交拆分是最小建议，可继续拆细，不把多个独立行为揉成一次提交。
3. **先设计后实现**：涉及数据模型、模块边界或执行语义时，先改 `docs/design/overview.md`，再写代码。
4. **先正常后异常**：每个能力除了成功路径，还必须验证参数错误、依赖不可用、重复执行和取消/恢复。
5. **不带债收尾**：编译通过不代表完成；阶段声明的自动化测试、故障验证、页面验收和文档更新全部完成才算完成。
6. **不拿真实模型做脆弱测试**：自动化测试使用本地假 HTTP 服务或测试替身；真实模型只做可重复的冒烟与质量评测，不断言逐字回答。
7. **数据库不降级**：repository 与迁移测试使用真实 PostgreSQL/pgvector，不用 SQLite 替代，避免方言与并发行为失真。

## 2. 固定质量门禁

后端每个阶段都执行：

```bash
cd backend
go build ./...
go vet ./...
go test -race -count=1 ./...
```

前端自 Phase 3 起执行：

```bash
cd frontend
npm run lint
npm run test
npm run build
```

按阶段能力补充以下测试层次：

| 层次 | 必须覆盖的内容 |
|---|---|
| 单元测试 | 纯函数、状态机、边界值、错误分支；bug 修复必须带回归测试 |
| 数据库集成测试 | 迁移、约束、事务、条件更新、并发领取、回滚；使用真实 PostgreSQL |
| HTTP 契约测试 | 统一信封、状态码、参数校验、错误码、request_id |
| 前端测试 | 关键交互、空态、加载态、失败态；不只测组件能渲染 |
| 故障注入 | 模型超时、进程重启、连接断开、重复消息、依赖宕机 |
| AI 质量评测 | 固定小样本集；检查引用、结构、召回与约束保留，不断言模型逐字输出 |

每个阶段收尾时，在对应章节记录实际执行的命令、代表性 curl / 页面结果、已知限制；遗留问题同步到 `AGENTS.md`。

## Phase 1 工程基线纠偏（已完成，2026-11-08）

**目标**：先把现有骨架中的确定性缺陷修掉，建立后续所有阶段共用的测试习惯。

**范围**：中间件顺序、非法配置报错、关键错误路径回归测试、启动与排错说明。

**提交拆分**
1. `fix: 修正中间件顺序使 panic 请求保留访问日志`
2. `test: 补充 panic 日志与 request_id 回归用例`
3. `fix: 配置解析失败时启动报错`
4. `test: 补充配置边界与非法值用例`
5. `docs: 完善本地启动与常见故障说明`

**质量验证**
- panic 请求同时有访问日志、stack、request_id，客户端不收到内部堆栈。
- 非法整数/时长、空密码、非法日志级别均启动失败；未设置的普通默认值仍正常。
- 重复运行测试无端口与全局状态污染，`-race` 通过。

**退出标准**：`AGENTS.md` 中两个已知代码问题关闭，且都有“旧实现会失败”的回归测试。

## Phase 2 数据迁移与系统状态

**目标**：建立可信的数据库变更机制；后续加表不再依赖手工 SQL。

**范围**：`migrations/`、`cmd/migrate/`、pgvector 扩展、存储与模型配置校验、`/system/status`、只读设置接口。

**提交拆分**
1. `feat: 引入 SQL 迁移与迁移执行入口`
2. `feat: 启用 pgvector 扩展并记录迁移版本`
3. `feat: 新增模型、存储与预算配置校验`
4. `feat: 新增系统状态与只读设置接口`
5. `test: 覆盖迁移回滚与脏版本恢复`
6. `docs: 编写迁移操作与恢复说明`

**质量验证**
- 空库执行 `up → down → up`；重复 `up` 不重复建表。
- 中断迁移后能识别 dirty 状态，文档中的恢复步骤经过实测。
- `/system/status` 分别报告数据库、vector 扩展、迁移版本；模型未配置时显示未配置，不伪造连通成功。
- 密钥只返回脱敏结果，日志与响应均不泄露 `.env` 内容。

**退出标准**：全新环境只按 README 即可完成迁移；状态接口能准确定位“库不通、扩展缺失、迁移落后”三类问题。

## Phase 3 前端工程与产品骨架

**目标**：建立可长期演进的前端基础，而不是堆六个静态页面。

**范围**：Vite + React + TS、Tailwind、shadcn/ui、Router、TanStack Query、Vitest、统一 API 客户端、六页导航与 Settings 状态页。

**提交拆分**
1. `feat: 初始化 React TypeScript 前端工程`
2. `feat: 实现应用布局与六页路由`
3. `feat: 封装 API 客户端与统一错误处理`
4. `feat: 实现系统状态设置页`
5. `test: 覆盖路由、请求失败与空态交互`
6. `docs: 编写前端开发与测试说明`

**质量验证**
- 六页可直接访问、刷新不 404；窄屏下导航不遮挡主内容。
- 后端未启动、返回非 2xx、返回业务错误码时均有明确失败态。
- 页面不造假数据；接口未实现时显示“尚未接入”。
- API 类型无散落 `any`，生产构建无 TypeScript 错误。

**退出标准**：前端能真实读取 `/system/status`，lint/test/build 全绿，后续页面只需在既有规范内扩展。

**目标**：完成最小的 Knowledge 垂直切片：文本进来，解析、切分、落库、可见。

**范围**：documents/document_chunks、文件存储、Markdown/TXT 解析、标题/段落切分、文件与笔记同步导入、基础列表/详情/分块页。

**提交拆分**
1. `feat: 新增文档与分块模型及迁移`
2. `feat: 实现本地文件存储与内容哈希`
3. `feat: 实现 Markdown 与纯文本解析`
4. `feat: 实现保留偏移的分块器`
5. `feat: 实现文件与笔记同步导入接口`
6. `feat: 实现文档列表详情与分块预览`
7. `test: 覆盖解析切分与入库事务边界`

**质量验证**
- 标题、空段落、超长段落、代码块、中文与 emoji 的偏移准确。
- 入库任一步失败时事务回滚；孤儿文件有明确清理策略并经过测试。

- 此阶段不要求 embedding 和搜索，页面明确显示尚未索引。

**退出标准**：一个 Markdown 文件和一条笔记可从页面上传并查看全部分块，分块能精确映射回原文。

## Phase 5 多格式与导入可靠性

**目标**：把导入从“支持文本”扩展为可反复操作的文档管理。

**范围**：PDF 文本层、网页正文抽取、重复导入、删除、重索引、标签与分类筛选。

**提交拆分**
1. `feat: 实现 PDF 文本层解析`
2. `feat: 实现网页正文抓取与抽取`
3. `feat: 实现文档幂等导入与重复检测`
4. `feat: 实现文档删除与重新索引`
5. `feat: 实现分类标签与列表筛选`
6. `test: 覆盖解析失败与重复操作`

**质量验证**
- 无文本层 PDF 明确报不支持，不静默生成空文档；网页超时、重定向、非 HTML 均有错误分支。
- 相同内容重复上传返回既有文档，不产生第二组分块。
- 重索引采用新结果完整后替换，失败时旧可用数据不丢失。
- 删除文档同时处理分块与原始文件，重复删除结果明确。

**退出标准**：文件/笔记/网页三种来源均可管理；重复上传、重复删除、连续重索引不会留下孤儿或不一致数据。

## Phase 6 本地异步任务

**目标**：将耗时导入移出 HTTP 请求，先靠 PostgreSQL 建立可恢复的任务语义，不急于引入 MQ。

**范围**：jobs、进程内 worker、租约领取、退避重试、取消、重启补扫、文档任务状态展示。

**提交拆分**
1. `feat: 新增异步任务模型与迁移`
2. `feat: 实现任务条件领取与租约续约`
3. `feat: 实现进程内 worker 与优雅停止`
4. `feat: 文档导入切换为异步任务`
5. `feat: 实现任务重试取消与失败展示`
6. `test: 覆盖并发领取与进程重启恢复`

**质量验证**
- 多 worker 并发时同一 job 只被一个领取；重复提交有 dedupe 行为。
- worker 宕机后，过期租约可被接管；服务重启后 queued/running 任务有明确恢复路径。
- 取消能传播到解析过程；达到 max_attempts 后停止重试并保留错误码。
- HTTP 202 返回 document 与 job_id，前端轮询状态，不阻塞上传请求。

**退出标准**：停库、worker 异常退出、强停服务进程三类故障后，任务状态都可解释、可恢复，不出现永远 running。

## Phase 7 Embedding 与向量索引

**目标**：建立可替换的 Embedding Provider，并把向量写入做成可重跑的独立步骤。

**范围**：OpenAI 兼容 Embedding 客户端、批量与限流、向量列/HNSW、用量账本、重建向量、Embedding 设置页。

**提交拆分**
1. `feat: 实现 Embedding 客户端与超时重试`
2. `feat: 新增向量列索引与用量账本`
3. `feat: 实现分块批量向量化`
4. `feat: 实现向量重建与模型设置接口`
5. `feat: 实现 Embedding 设置与任务进度`
6. `test: 覆盖批处理失败与维度不一致`

**质量验证**
- 假服务覆盖 401、429、500、超时、空向量、错误维度、部分批次失败。
- 重试只针对可重试错误；批量失败可重跑，不产生重复分块，账目能对应到具体任务与模型响应。
- 维度不匹配在写库前失败并给出明确错误；换模型不被当作普通配置热切换。
- token 与 cost_micros 使用整数记账，API Key 不进入日志。

**退出标准**：所有 ready 文档都有完整向量或明确失败状态；重建过程可恢复，真实 provider 冒烟通过。

## Phase 8 混合检索与引用定位

**目标**：把“有向量”变成“搜得准、说得清为什么命中”。

**范围**：tsvector/GIN、向量召回、RRF、过滤与分页、检索 API、搜索页与原文高亮、固定评测集。

**提交拆分**
1. `feat: 新增全文检索列与索引`
2. `feat: 实现向量与全文两路召回`
3. `feat: 实现 RRF 融合与过滤`
4. `feat: 实现检索接口与原文定位`
5. `feat: 实现知识搜索与结果高亮`
6. `test: 建立混合检索质量回归集`

**质量验证**
- 评测集同时包含专名/版本号精确查询、同义改写、无结果查询、标签过滤。
- 只有 ready 文档可被命中；空向量、空关键词、非法 top_k 有确定行为。
- 同一查询结果顺序稳定；RRF 单元测试覆盖单路命中与并列名次。
- 点击结果能定位 document_id + seq + offset，不依赖模型生成位置。

**退出标准**：固定样本全部达到预设命中要求；两路检索可分别调试，融合结果与引用定位可复现。

## Phase 9 RAG 问答与知识闭环

**目标**：完成不依赖 Agent 的知识问答链路，把引用正确性单独验证清楚。

**范围**：LLM 客户端、检索上下文组装、引用校验、无依据拒答、问答接口与页面、LLM 设置与 Dashboard 最近知识。

**提交拆分**
1. `feat: 实现 LLM 客户端与结构化错误`
2. `feat: 实现知识问答上下文组装`
3. `feat: 实现带引用回答与引用校验`
4. `feat: 实现知识问答接口与页面`
5. `feat: 实现 LLM 设置与连通性测试`
6. `test: 建立问答引用与拒答评测`

**质量验证**
- 模型返回非法编号、伪造 document_id、无引用、无依据问题时，代码能识别并降级。
- top 5–8 分块按文档聚合，超长上下文按预算截断。
- 模型超时/限流不影响已有文档与检索；失败响应不暴露 provider 原文和密钥。
- Dashboard 只展示真实最近文档，问答页可打开引用原文。

**退出标准**：知识库从导入到检索再到可追溯问答完整可用；固定评测集不存在假引用被当作成功的情况。

**目标**：先建立可信的记忆数据与修订机制，再让模型参与写入。

**范围**：memories/memory_versions、部分唯一索引、手动增改归档、来源与版本 API、Memory 页面。

**提交拆分**
1. `feat: 新增记忆与版本模型及迁移`
2. `feat: 实现记忆手动新增与来源记录`
3. `feat: 实现记忆修订归档与版本链`
4. `feat: 实现记忆管理页面`
5. `test: 覆盖部分唯一索引与版本并发`

**质量验证**
- 同一 `(kind,key)` 并发写入最多一条 active；空 key 不被误限制。

- 来源不存在或格式非法时拒绝写入；手动记忆 source_type=manual。

**退出标准**：用户不经过模型即可完整管理记忆，每次变化都有版本，任何记忆都能追溯来源。

## Phase 11 记忆提炼与冲突治理

**目标**：让模型只产候选，让代码决定校验、合并与落库。

**范围**：结构化提炼、evidence 回查、重要性阈值、新增/合并/取代、提炼任务与频控。

**提交拆分**
1. `feat: 实现记忆候选结构化提炼`
2. `feat: 实现候选校验与证据回查`
3. `feat: 实现记忆新增合并与取代`
4. `feat: 接入记忆提炼任务与频控`
5. `test: 建立提炼冲突与幻觉样本集`

**质量验证**
- schema 缺字段、超长 content、非法 kind、伪造 evidence、低重要性候选均不会入库。
- “Node 为主”到“Go 为主”的冲突走 supersede，不留下两条 active。
- 同一输入重复提炼幂等；同会话 10 分钟内重复触发受频控。
- 此阶段使用手动文本与文档摘要验证；对话结束触发在 Phase 14 接线。

**退出标准**：新增、合并、取代、丢弃四类结果都有自动化样本；模型不能直接指定 SQL 或绕过版本链。

**提交拆分**
1. `feat: 实现记忆召回打分与过滤`
2. `feat: 实现召回预算与统计更新`
3. `feat: 实现召回调试与来源展示`
4. `test: 建立记忆召回质量回归集`

**质量验证**
- archived/superseded 不参与召回；kind 与 query 空值行为明确。
- 分数各分项可在调试接口查看；top_k 与字符/token 上限不可被客户端无限放大。
- 并发召回统计不会丢更新；统计更新失败不泄露内部错误。
- 评测覆盖相关记忆、相似但冲突记忆、无关记忆和预算不足。

**退出标准**：固定查询的召回顺序与理由可复现，进入后续 Agent 的记忆数量与长度都有硬上限。

## Phase 13 会话与 Agent 最小闭环

**目标**：先跑通不带工具的对话运行时，分离 chat 与 agent，避免一次性引入全部复杂度。

**范围**：conversations/messages/agent_runs/agent_events、Eino Runner 最小封装、SSE、基础 Chat 页面、断连取消。

**提交拆分**
1. `feat: 新增会话消息与运行事件模型`
2. `feat: 实现会话与消息管理接口`
3. `feat: 接入 Eino Runner 最小对话链路`
4. `feat: 实现事件落库与 SSE 推送`
5. `feat: 实现基础对话页面`
6. `test: 覆盖事件顺序与断连取消`

**质量验证**
- 同一 run 事件 seq 连续且唯一，先落库再推送；刷新后消息仍在。
- 浏览器断连后 run 在约定时间内 cancelled，模型流与 goroutine 均退出。
- chat 包不 import eino，agent 包不 import gin。
- 此阶段只做最近消息窗口和普通对话，不提前实现工具、审批与上下文摘要。

**退出标准**：一次真实模型对话可从页面发起、流式显示、落库、刷新恢复；断开连接不会遗留运行中的 run。

## Phase 14 工具与运行安全

**目标**：给 Agent 加上受控的只读能力与不可绕过的资源上限。

**范围**：search_knowledge/read_document/search_memory、参数校验、tool_audits、max_steps/token/timeout、主动取消、执行轨迹、对话后记忆提炼。

**提交拆分**
1. `feat: 注册知识检索与文档读取工具`
2. `feat: 注册记忆召回工具`
3. `feat: 实现工具审计与运行轨迹`
4. `feat: 实现步数预算与整体超时`
5. `feat: 实现主动取消与对话后记忆提炼`
6. `test: 覆盖工具越界与三重上限`

**质量验证**
- 非法 JSON、负数 top_k、超长返回、模型伪造参数不会穿透到 repository。
- 预算在每次模型调用前检查；100 token 小预算不会继续发起下一次调用。
- 达到步数、预算、超时、主动取消分别落不同 error_code，部分输出与审计保留。
- 对话结束只触发一次 memory_extract，失败不反向破坏已完成回答。

**退出标准**：Agent 能使用知识与记忆回答；所有工具调用有审计，四种终止路径均通过自动化与日志验证。

## Phase 15 Checkpoint 与人工审批

**目标**：实现真正可恢复的 Human-in-the-loop，而不是内存里等待一个 HTTP 请求。

**范围**：agent_checkpoints、agent_approvals、save_memory 写工具、批准/拒绝/过期、Resume、事件断点续传与审批卡片。

**提交拆分**
1. `feat: 实现 Agent Checkpoint 存储`
2. `feat: 新增审批模型与状态机`
3. `feat: 实现 save_memory 审批门`
4. `feat: 实现审批后恢复与事件续传`
5. `feat: 实现审批卡片与执行回放`
6. `test: 覆盖重启恢复与审批并发`

**质量验证**
- 批准后只执行一次写操作；拒绝后模型收到拒绝观察且记忆不落库。
- 两个并发审批请求只有一个生效；过期审批不能恢复。
- 进程在 waiting_approval 状态重启后仍可 Resume；checkpoint 损坏时安全失败。
- SSE 从 since_seq 重连不重复、不漏事件，前端可完整回放。

**退出标准**：写操作没有绕过审批的路径；批准、拒绝、过期、重启恢复四条链路均实测通过。

## Phase 16 MQ 与后台可靠执行

**目标**：在已有 jobs 真相模型上增加 RabbitMQ 唤醒与后台 workflow，不推翻前期任务语义。

**范围**：outbox_events、relay、MQ 消费者、幂等与重投、死信、后台只读 workflow、队列状态与设置展示。

**提交拆分**
1. `feat: 实现事务 Outbox 与投递中继`
2. `feat: 接入 RabbitMQ 任务派发`
3. `feat: 实现幂等消费与失败重投`
4. `feat: 实现死信与队列状态观测`
5. `feat: 实现后台 workflow 运行入口`
6. `test: 覆盖消息丢失重复与 broker 重启`

**质量验证**
- 业务提交成功但 MQ 不可用时有 outbox 补投；消息丢失靠 jobs 补扫兜底。
- 同一消息重复投递不重复执行副作用；broker 重启后任务最终可完成。
- 死信可查看原因并人工重投；relay/consumer 停止时不丢未确认消息。
- 后台 workflow 不随 SSE/HTTP 断连取消，与前台 react 的生命周期明确区分。

**退出标准**：文档入库与后台 workflow 都走统一可靠任务链路；DB、MQ、进程分别故障时均有恢复验证。

## Phase 17 Action 领域与任务管理

**目标**：让目标、计划、任务先成为可独立使用、规则完整的产品模块。

**范围**：goals/plans/tasks/task_dependencies/task_events、状态机、依赖环检测、任务板、目标计划与 Tasks 页面。

**提交拆分**
1. `feat: 新增目标计划任务模型及迁移`
2. `feat: 实现目标计划与任务管理接口`
3. `feat: 实现任务状态机与事件记录`
4. `feat: 实现任务依赖与环检测`
5. `feat: 实现 Tasks 页面与任务看板`
6. `test: 覆盖状态流转依赖与删除边界`

**质量验证**
- A 依赖 B、B 依赖 A 等直接与间接环均被拒绝；自依赖同样拒绝。
- 依赖未完成时不能 done；blocked/doing/done/cancelled 的合法迁移有表驱动测试。
- 删除/归档目标和计划不产生孤儿任务；并发状态更新不覆盖他人的新版本。
- 看板与列表使用同一统计口径，空态与失败态完整。

**退出标准**：不调用模型也能完成目标—计划—任务全流程，所有状态变化可追溯且依赖不失真。

## Phase 18 AI 计划与行动闭环

**目标**：把 Agent 接入 Action，但计划必须草案先行，写操作必须审批。

**范围**：list_tasks/get_task 读工具、create_goal/create_plan/create_task/update_task 写工具、计划草案编辑与确认、Dashboard 聚合。

**提交拆分**
1. `feat: 注册行动查询工具`
2. `feat: 实现 AI 计划草案生成`
3. `feat: 实现计划编辑确认与批量落库`
4. `feat: 注册行动写工具并接入审批`
5. `feat: 实现 Dashboard 目标与今日待办`
6. `test: 覆盖计划确认幂等与 Agent 越权`

**质量验证**
- 草案可增删改，确认前不出现在正式任务列表；重复确认不重复建任务。
- Agent 不能直接 approved，不能删除目标/计划，不能绕过依赖检查。
- 批量落库任一任务失败则整体回滚；审批参数与最终写入内容一致。
- “一个月学习 Go 并发”样本能结合记忆与知识生成草案，用户修改后形成真实任务链。

**退出标准**：从目标提出到草案、修改、审批、任务执行、Dashboard 进度全部闭环，越权路径有回归测试。

## Phase 19 Context 上下文工程

**目标**：基于真实长对话样本优化上下文，不在早期凭空调参。

**范围**：ctxbuild、分段预算、token 估算校准、conversation_summaries、摘要任务、上下文构成记录与调试视图。

**提交拆分**
1. `refactor: 收口对话上下文构建入口`
2. `feat: 实现上下文分段预算与裁剪`
3. `feat: 实现对话摘要生成与注入`
4. `feat: 实现上下文构成记录与调试`
5. `test: 建立长对话与约束保留回归集`

**质量验证**
- system/记忆/知识/历史/摘要各段实际 token 可查看，总预算不可突破。
- 连续 30 轮样本的 prompt_tokens 不随历史单调失控；否定约束与目标在摘要后仍保留。
- 摘要失败降级为安全截断且不阻塞对话；原消息永不删除。
- 估算值与真实 usage 的偏差有记录，模型调用失败不写伪用量。

**退出标准**：固定长对话评测通过，任何分支都不超预算；用户能知道本次回答使用了哪些知识与记忆。

## Phase 20 Insights 个人洞察

**目标**：先保证统计真实，再让模型做总结；没有数据时明确说没有。

**范围**：周期统计、insights、定时与手动生成、学习进度、知识覆盖与简单关联、Dashboard/Insights 展示。

**提交拆分**
1. `feat: 实现周期统计聚合与洞察模型`
2. `feat: 实现周期总结生成任务`
3. `feat: 实现学习进度与知识覆盖分析`
4. `feat: 实现洞察展示与 Dashboard 卡片`
5. `test: 覆盖统计口径周期边界与幂等`

**质量验证**
- 统计结果与 tasks/documents/memories 手工核对一致，UTC 周期边界明确。
- 同一周期重复生成按唯一约束更新或复用，不产生重复卡片。
- 空数据返回“暂无足够数据”，模型不得编造活动；模型失败不影响统计查询。
- 关联发现只基于真实向量/标签结果并展示依据，不宣称因果。

**退出标准**：日报/周报可自动生成且能手动重跑；所有数字有来源，所有建议能区分统计事实与模型判断。

## Phase 21 产品化与长期运行

**目标**：把已验证能力变成可部署、可备份、可排查、可持续维护的产品。

**范围**：后端与前端镜像、全栈编排、数据导出与备份恢复、运行指标、核心链路端到端回归、部署与使用文档。

**提交拆分**
1. `feat: 实现后端前端镜像与全栈编排`
2. `feat: 实现个人数据导出与备份能力`
3. `feat: 补充关键链路日志与运行指标`
4. `test: 建立核心用户链路端到端回归`
5. `test: 执行故障恢复与长稳验证`
6. `docs: 完善部署使用备份与接口手册`
7. `chore: 整理依赖并完成发布前检查`

**质量验证**
- 干净环境按文档启动全栈，迁移与初始配置不依赖未说明的手工步骤。
- 端到端覆盖导入→检索→问答、对话→记忆、目标→审批→任务、周期洞察。
- 备份在另一套干净数据卷上真实恢复；导出内容不含 API Key 等秘密。
- request_id/run_id/job_id 可串联日志；队列积压、失败率、模型用量可观察。
- 服务重启、依赖短暂不可用、长时间空闲后再使用均通过验证。

**退出标准**：文档命令逐条实测，核心链路自动化回归全绿，备份恢复真实演练成功，没有未登记的高优先级问题。

## 4. 依赖与顺序约束

- **P1–3 是地基**：迁移、错误处理与前端请求约定不稳定，后续每个模块都会重复返工。
- **P4–6 先于 P7**：先有可靠文本与任务边界，再接向量，避免把解析故障和模型故障混在一起。
- **P8 先于 P9**：检索质量未达标时不能做 RAG，否则无法区分“搜错”与“答错”。
- **P10 先于 P11–12**：先有人工可修订的真相数据，再接自动提炼与召回。
- **P13 先于 P14–15**：最小对话闭环稳定后，才增加工具、预算、审批与恢复。
- **P16 复用 P6**：MQ 是增强唤醒与后台执行，不替代 jobs，不重写任务状态机。
- **P17 先于 P18**：Action 自身规则正确后，Agent 才能通过 service 安全操作。
- **P19 放在真实对话之后**：用 P13–18 产生的样本调上下文，不提前做无效优化。
- **P20 靠真实数据**：没有知识、记忆和任务积累时，不做伪造洞察。
- **Redis 仍非必选**：只有真实瓶颈出现时单独评审，不因技术栈列表提前引入。

## 5. 阶段内工作方式

1. **开始前**：重读本阶段目标与上阶段验收记录，列出本轮不改的范围。
2. **实现中**：先补失败测试或最小复现，再实现；外部依赖的官方用法先确认再引入。
3. **自审时**：检查错误路径、资源关闭、context 传播、并发与重复执行，不只看 happy path。
4. **收尾时**：跑固定门禁和本阶段专项验证，更新进度、导读与已知问题。
5. **发现跨阶段问题**：能小步修复就单独 fix；需要改设计时先停下当前功能，完成设计评审后再继续。

## 6. 变更管理

- 任何“提前实现后续阶段能力”的想法先记录，不直接进代码。
- 阶段范围可以缩小或继续拆，但不能通过删除测试、降低样本要求来宣布完成。
- 阶段目标调整必须同步修改本文件、`docs/design/overview.md` 与 README 路线引用。
- 真实模型评测失败时先分类为检索、上下文、提示词、结构化输出或运行时问题，再进入对应修复提交，不盲目调参。
