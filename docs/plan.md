# Noema 开发计划

计划粒度到**提交**：每次提交只做一件事，可独立回滚。里程碑之间不允许携带未完成的半成品。

通用收尾门槛（每个里程碑都必须满足）：

```bash
cd backend
go build ./...
go vet ./...
go test -race -count=1 ./...
```

外加该里程碑声明的 curl / 日志验证记录，三者缺一不宣布完成。

## M0 骨架（已完成）

配置加载、结构化日志、中间件、统一响应、健康检查、优雅关闭、PostgreSQL 连通。
仓库结构：前后端分离，Go module 为 `github.com/luo303/noema/backend`。

## M1 数据层与迁移

**目标**：领域模型落地，数据库表可重复初始化，数据访问层可用。

**交付物**
- `backend/migrations/`：正向 + 回滚 SQL
- `backend/cmd/migrate/`：迁移执行入口（`golang-migrate/migrate`）
- `backend/internal/model/`：document、run、step、note 模型与状态常量
- `backend/internal/repository/`：document、run 数据访问

**提交拆分**
1. `fix: 修正中间件顺序使 panic 请求保留访问日志`
2. `fix: 配置整型解析失败时启动报错`
3. `feat: 新增领域模型与状态常量`
4. `feat: 引入 SQL 迁移与初始化表结构`
5. `feat: 实现文档与任务的数据访问层`
6. `test: 覆盖任务抢占的条件更新语义`

**验证**：迁移可重复执行与回滚；抢占 SQL 在并发下只有一个会话返回 `RowsAffected=1`。

**退出标准**：表结构与设计文档一致，条件更新有测试背书。

## M2 文档上传与任务创建

**目标**：跑通"上传 → 落盘 → 建档 → 创建任务"，重复上传不产生重复任务。

**提交拆分**
1. `feat: 实现文档上传接口与落盘存储`
2. `feat: 基于内容 hash 的上传幂等`
3. `feat: 创建加工任务并返回受理响应`
4. `feat: 文档列表与详情查询`
5. `test: 上传与重复提交的接口测试`

**验证**

```bash
curl -F "file=@./README.md" http://localhost:8080/api/v1/documents   # 202，返回 run_id
curl -F "file=@./README.md" http://localhost:8080/api/v1/documents   # 同 hash，复用文档，不新建任务
curl http://localhost:8080/api/v1/documents                          # 分页列表
```

**退出标准**：重复上传幂等；超大文件与不支持的类型返回 400；任务初始状态为 `queued`。

## M3 加工流水线（FakeRunner）

**目标**：不依赖外部模型，跑通"抢占 → 执行 → 进度 → 取消"全链路。

**交付物**：`internal/runner/`（接口与 FakeRunner）、`internal/worker/`（抢占、执行、取消）、run 相关查询接口。

**提交拆分**
1. `feat: 定义 Runner 接口与假实现`
2. `feat: 实现任务抢占与租约管理`
3. `feat: 实现步骤执行与进度落库`
4. `feat: 实现任务取消与 context 中断`
5. `feat: 任务状态与步骤明细查询接口`
6. `test: 并发抢占与取消的回归测试`

**验证**：两个 worker 同时启动，同一 run 只被执行一次；执行中调用 cancel，正在进行的步骤在秒级内中断；kill 掉 worker 后租约过期，任务被另一个 worker 接管且不重复记账。

**退出标准**：上述三条有日志或测试记录；`-race` 无数据竞争。

## M4 真实模型接入与记账

**目标**：接入真实模型，成本可核算、可封顶。

**提交拆分**
1. `feat: 接入 OpenAI 兼容协议客户端`
2. `feat: 用量流水与预算闸门`
3. `feat: 模型调用超时与有限重试`
4. `test: 记账与预算耗尽的单元测试`

**配置**：`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` / `LLM_TIMEOUT`（随第 1 笔提交同步进 `.env.example`，不预留未读取的配置项）。

**验证**：同一文档分别用 FakeRunner 与真实模型加工，步骤产出结构一致；预算设为极小值时任务以 `BUDGET_EXCEEDED` 终止且不再发起调用。

**退出标准**：无 API Key 时自动回退 FakeRunner 并在日志中明示；`usage_ledger` 与 `runs.used_cents` 对账一致。

## M5 笔记检索

**目标**：加工产物可检索、可导出。

**提交拆分**
1. `feat: 笔记落库与全文检索索引`
2. `feat: 笔记列表、详情与导出接口`
3. `feat: 文档删除与重新加工`
4. `test: 检索与标签筛选测试`

**验证**：`GET /api/v1/notes?q=事务` 命中预期笔记；`tag` 筛选与全文条件可组合；导出文件为合法 Markdown。

## M6 Redis

**目标**：缓存、限流、分布式租约就位，并有降级行为。

**提交拆分**
1. `feat: 接入 Redis 客户端与生命周期管理`
2. `feat: 任务进度缓存与失效策略`
3. `feat: 模型调用并发限流`
4. `feat: 分布式租约续期与崩溃接管`
5. `test: 缓存一致性与限流验证`

**验证**：停掉 Redis 后服务不启动失败、进度查询回源数据库并记录降级日志；限流阈值内外的请求数符合预期；两个进程下同一 run 仍只被执行一次。

## M7 RabbitMQ 与事件推送

**目标**：任务分发与状态推送解耦，异常路径可验证。

**提交拆分**
1. `feat: 接入 RabbitMQ 与连接生命周期管理`
2. `feat: 任务消息生产与消费`
3. `feat: 消费重试与死信队列`
4. `feat: Outbox 中继与幂等消费`
5. `feat: 任务进度 SSE 推送`
6. `test: 重复投递与重启恢复验证`

**验证**：同一消息重复投递不重复记账；消费者进程重启后未确认消息被重新投递；死信可查询、可人工重放；SSE 断连可续传。

## M8 控制台与工程完善

**目标**：非命令行用户可用，服务可一键部署。

**提交拆分**
1. `feat: 后端静态资源托管`
2. `feat: 文档上传与进度展示页面`
3. `feat: 笔记检索与导出页面`
4. `feat: 访问令牌认证`
5. `feat: 服务容器化与一键启动`
6. `test: 关键链路集成测试`
7. `docs: 完善使用手册与接口文档`

**验证**：浏览器完成"上传 → 看进度 → 读笔记 → 导出"闭环；`docker compose up -d` 一条命令起全栈；未带令牌的请求返回 401。

## 里程碑依赖与顺序约束

- M3 之前不引入 Redis / RabbitMQ，先用 PostgreSQL 保证正确性，避免多组件同时排错。
- M4 的真模型接入在 M3 之后，确保流水线本身先被 FakeRunner 验证。
- M6、M7 是对已正确链路的增强，不得借机重写 M3 的执行语义。
- 前端在 M8 才正式开发；此前仅用 curl 与日志验证后端。

## 变更管理

- 里程碑内的设计调整先改 `docs/design/overview.md`，再改代码，避免文档失实。
- 每个里程碑结束后更新本文件状态与 `AGENTS.md` 的进度行。
- 出现无法当场解决的问题，记入 `AGENTS.md` 的已知问题表并标注处理时机，不靠记忆留存。
